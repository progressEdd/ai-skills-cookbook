## Research how docs are setup
### Matt Pocock's website (aihero.dev)
- Neither GitBook nor GitWikis — it's a **custom Next.js app** (hand-built course platform)
  - Fingerprints: `/_next/static/chunks/*.js` assets, `__next` markers (App Router), Cloudinary for images (`res.cloudinary.com/total-typescript/...`)
  - Custom course-platform chrome: "Install this skill" blocks, skill pagination (`01 / 25`), copy-buttons for `npx skills@latest add mattpocock/skills`
  - The [skills docs section](https://www.aihero.dev/skills-setup-matt-pocock-skills) is just pages in that app, likely rendered from markdown in his repo
- Side note on the content itself: the page documents his `/setup-matt-pocock-skills` skill from [mattpocock/skills](https://github.com/mattpocock/skills) — a run-once, per-repo setup skill that records 3 decisions (issue tracker, triage labels, domain docs layout) as plain markdown under `docs/agents/`. Skills stay identical across repos; only the committed config varies.

### Software Mansion's guide (agentic-engineering.swmansion.com)
- **Astro + Starlight** docs site (markdown-based, free/OSS)
  - Fingerprints: ~420 `astro` references and 35 `starlight` ones in the page HTML — Starlight's signature sidebar / "On this page" / theme-toggle layout
  - Same stack family as Astro, Vite, and many OSS project docs
  - Source is public: [software-mansion/agentic-engineering](https://github.com/software-mansion/agentic-engineering/tree/main)
- Takeaway for this repo: Starlight is a candidate model if we want hosted docs for the cookbook; GitBook/GitWikis only make sense if we want hosted docs with zero setup
