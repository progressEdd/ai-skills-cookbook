### `origin/starter-skills` vs `starter-skills` — proven with experiments
- Question from the crash course's merge step: why not just `starter-skills`, or `origin starter-skills`? Tested in a plain fresh clone *and* the real repo (`02-worktrees/merge-lab`, branched off `master`):
  - `git merge starter-skills` in a plain clone → fails (`not something we can merge` — no remote fallback, unlike `git checkout`)
  - `git merge origin starter-skills` (space form) → fails identically; `git merge` treats each word as an independent ref
  - `git merge origin master` "never erroring" was a red herring: `origin` resolves to the default branch via `origin/HEAD`, so both words are already ancestors → silent *Already up to date* no-op
  - `git merge origin/starter-skills` works for everyone; if `git setup-worktrees` ran, the local `starter-skills` works too (merging a branch checked out in another worktree is fine)
- The crash course's parenthetical was rewritten to teach the "why", cover both spellings, and reference the `setup-worktrees` path

### Rebase use-cases, demoed in `merge-lab`
- Scenario: agent makes a branch off your `course-edd` to modify `03-project-instructions.md`. If `course-edd` moved meanwhile: on the agent branch `git rebase course-edd` (paused once on a real conflict — resolved, `git rebase --continue`), then on `course-edd` a plain `git merge` lands it as **Fast-forward** → linear history, as if the agent committed directly
- If the base didn't move, rebase is a no-op and the merge still fast-forwards — so rebase is the *prep* step, only needed when history moved
- Takeaway recorded: branch first (manually or by instructing the agent) before letting it modify anything

### Review-before-merge toolkit (all demoed, then demo branches cleaned up)
- `git log <base>..<branch>` — which commits would come in (read-only, works before either command)
- `git diff <base>...<branch>` / `git show <hash>` — what exactly would change
- `git merge --no-commit --no-ff` — apply the merge to the working tree but stop before committing, for inspection; `git merge --abort` leaves the parent untouched
- Corrected mental model: rebase is history-shaping, not review — it shows nothing when clean and only pauses on conflicts
